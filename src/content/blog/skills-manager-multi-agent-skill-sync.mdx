## 30 秒看懂
如果你同时用 Claude Code、Codex 和 Cursor，Skill 很容易变成三份文件。改一次规则，还得记得同步三次。
Skills Manager 把这些 Skill 收进一个本地中央库。你选择哪些 Skill 要给哪个 Agent，再按全局或项目作用域同步。它还支持 Preset、Git 备份和 CLI。
所以它解决的不是“怎么写 Skill”，而是“写完以后怎么长期管理”。
## 为什么有意思
Agent Skills 正在变成真实的配置资产。它们有来源、版本、项目作用域、同步状态和备份需求。
Skills Manager 没有重新设计 Skill 格式。它把管理层补上了。这个方向和包管理器很像，但对象换成了 Agent 的行为说明、工具规则和工作流。
v1.39.0 里那个 CRLF、LF 修复很说明问题。多台电脑、多种 Agent 一起用时，真正麻烦的往往不是 Prompt 怎么写，而是文件怎样保持一致。
## 3 个值得借鉴的设计
### 中央库和目标目录分开
Skill 先进入中央库，再同步到各个 Agent。这样修改源内容时，不需要手工维护多份副本。
### 工作区有明确作用域
它区分全局、项目和链接工作区。通用 Skill 可以全局启用，项目专用 Skill 留在项目里。这个边界比把所有规则塞进一个目录更容易维护。
### 同步策略允许选择
用户可以选择复制或符号链接。复制更独立，链接更容易保持实时一致。v1.39.0 还处理了 Windows 和 macOS 行尾差异造成的假更新。
## 与我的连接
如果团队已经在 Notion 维护可读、可编辑的 Skill 源内容，同时还要给多个 Coding Agent 分发同一套 Skill，Skills Manager 更适合负责本地同步，而不是替代内容源。可以这样分工：
- Notion 保存可读、可编辑的 Skill 源内容和参考材料。
- 需要给本地 Coding Agent 执行的 Skill 导出成标准目录。
- Skills Manager 负责把这些目录同步到 Claude Code、Codex、Cursor 等工具。
这样 Notion 继续做内容中枢，Skills Manager 处理本地分发和版本一致性。

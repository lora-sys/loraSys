## 30 秒看懂
Coding Agent 一次改很多文件时，逐行展开整个 PR 会先消耗人的注意力。Jev-Code-Reviewer 先分析每个改动单元，再按策略映射成 P0、P1、P2。P0 表示需要人审，P1 表示建议人审，P2 表示机械性或证据更充分的改动。
Chrome 扩展保留 GitHub 原来的文件容器，只替换 diff 表格。默认展开 P0，P1 和 P2 收起。你可以随时切回未经改写的 GitHub diff。优先级表示先看哪里，不表示代码一定对或错。
## 为什么有意思
这个项目把问题定在人的审查时间上。它不另起一套 Review Dashboard。扩展直接嵌进 GitHub Files changed 页面，并保留文件名、折叠行为和原始 diff。报告不存在、过期或无法验证时，扩展继续显示源码。
这比把整个 PR 压成一段总结更容易核对。人可以先看 P0，需要时马上回到原始代码。
## 3 个值得借鉴的设计
第一，把注意力优先级和正确性判断分开。P0、P1、P2 只决定人先看哪里，避免把模型分类写成安全结论。
第二，失败时回到事实源。报告缺失、过期或本地服务不可用时，界面继续显示 GitHub 原始 diff。
第三，让辅助层贴在现有工作流上。它保留 GitHub 原来的文件结构，只替换 diff 内容，用户不用切到另一套控制台。

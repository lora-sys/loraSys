## Core idea
A coding agent that writes code and decides for itself whether the task is complete puts execution and acceptance in the same decision loop.
Foreman separates supervision. The worker does not need to pause while the supervisor thinks. Runtime events continuously enter a separate loop. The supervision layer sees only limited evidence, and a deterministic policy decides whether to continue, verify, stop, or request human help.
The most useful idea here is an independent control plane for an existing agent, rather than another agent that can write code.
## Understand it in 30 seconds
Give Foreman a ticket, specification, bug, or free-text task. The Codex worker writes code, edits files, and runs tests as usual.
Meanwhile, Foreman reads diffs, tests, worker output, and events. Jev judges whether the task is complete, whether testing is sufficient, and whether the worker is stuck or off track. Python policy then decides what happens next.
If verification is needed, it starts an independent verifier. If the worker gets stuck, it can stop or retry. When credentials, clarification, or human judgment are needed, it pauses and asks a person to handle them.
## Why it is interesting
Most coding agent harnesses put execution and the decision to stop in the same agent loop. An agent may stop before tests cover enough, or keep consuming context after it has finished.
Foreman does not rewrite Codex's reason, tool, and observe workflow or choose its files and tools. It reads limited evidence from outside and handles narrower questions, such as whether progress has stalled, whether independent verification is needed, and whether the requirements are met.
This separation lets developers test supervision policies and tune thresholds independently. The README also states the limits: Jev's judgment accuracy has not been established. A wrong judgment may stop a healthy worker or let incorrect work pass.
## 3 designs worth borrowing
### 1. Separate the worker and supervision loops
The coding agent continues its task. Foreman reads events in an independent asynchronous loop, without making the worker wait for an extra model after every step.
### 2. The model judges; policy acts
Jev produces judgments. Python policy decides whether to stop the worker, start a verifier, retry, or end the task. The probabilistic model does not directly control executable actions.
### 3. Give supervision context explicit limits
Foreman does not send the entire repository to the supervision model. It provides only the task, recent output, a bounded diff, changed files, tests, and events. The README sets explicit size limits for these observations.
## How this connects to my work
If you build agent harnesses or agent evaluations, you can apply Foreman's approach to your own runtime.
In a multi-agent system, for example, avoid making the execution agent decide whether its own work is done. Maintain separate supervisor state that accepts only task status, tool results, failure counts, cost, tests, and key events. The supervision model judges the situation; deterministic policy performs the actual stop, retry, verify, and escalate actions.
This can also work with Kitaru-style replay evaluation. Foreman supervises live runs, while replay evaluation checks whether the supervision policy often stops workers incorrectly, misses necessary stops, or ends tasks too early.

- Project name: Foreman.
- Maintainer: the GitHub organization `thruwire`.
- Official repository: [thruwire/foreman](https://github.com/thruwire/foreman). The repository is public and not archived.
- Core capability: a coding agent worker performs the actual software engineering task. Foreman reads runtime evidence in a separate asynchronous loop and assesses the current state of the work.
- Worker: V1 uses a locally installed Codex CLI and runs tasks through `codex exec`. The README also says the worker implementation can be replaced; the runtime depends only on a small worker protocol.
- Supervision inputs: the original task, worker summary, recent output, exit status, elapsed time, `git status`, bounded diff, changed files, validation results, and recent events.
- Judgment dimensions: whether implementation is complete, testing is sufficient, requirements are met, verification is needed, and the task can end; and whether the current worker is progressing, stuck, off track, or needs a human.
- Decision mechanism: Jev produces judgments. Deterministic Python policy decides the permitted actions, including continuing, starting a worker, starting an independent verifier, stopping, retrying, finishing, and handing off to a human.
- Demo: the repository provides `foreman demo --repo .`. The README explicitly says this demo needs no API key, network, Codex installation, or external repository.
- Persistence: each run is saved in `.foreman/runs/<run-id>/state.json` and `events.jsonl`.
- LICENSE: MIT.

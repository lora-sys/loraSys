## The 30-second version
When a coding agent changes many files at once, expanding an entire PR line by line consumes human attention. Jev-Code-Reviewer first analyzes each unit of change, then maps it through a policy to P0, P1, or P2. P0 means human review is required, P1 means human review is recommended, and P2 means a mechanical change or one with stronger supporting evidence.
The Chrome extension retains GitHub's original file containers and replaces only the diff tables. P0 is expanded by default; P1 and P2 are collapsed. You can return to the unmodified GitHub diff at any time. Priority tells you where to look first, not whether the code is necessarily right or wrong.
## Why it is interesting
This project focuses on human review time. It does not create another review dashboard. The extension embeds directly in GitHub's Files changed page and preserves filenames, collapse behavior, and the original diff. If a report is missing, stale, or unverifiable, the extension keeps displaying the source code.
That is easier to check than compressing an entire PR into a summary. Reviewers can start with P0 and return to the original code immediately when needed.
## 3 designs worth borrowing
First, separate attention priority from correctness judgments. P0, P1, and P2 determine only where people look first, so a model classification does not become a safety conclusion.
Second, return to the source of truth on failure. If a report is missing or stale, or the local service is unavailable, the interface keeps displaying GitHub's original diff.
Third, add assistance to the existing workflow. The extension retains GitHub's file structure and replaces only the diff content, so users do not need another console.

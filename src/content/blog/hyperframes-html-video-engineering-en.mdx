## The 30-second version
HyperFrames treats video as a code project that can be built.
An agent first generates HTML, CSS, asset references, and animation from a brief. It then uses the CLI to lint and preview. After checking the timeline and visuals, it renders an MP4.
It also packages common tasks as skills, such as turning a GitHub PR into an update video or a product website into a launch short.
Video generation therefore retains more than the final file. The intermediate structure can be versioned, inspected, and edited.
## Why it is interesting
Many AI video tools return a finished video directly. When the result is wrong, making a change usually means describing the request again.
HyperFrames keeps an editable intermediate layer. The video structure is HTML. Animations have explicit timing. Assets have file references. The CLI can check, preview, and render the project.
This structure is easier to automate in agent workflows. An agent can edit a segment, check it again, and handle only the project content that needs to change. People can also read the code and preview the result directly.
## 3 designs worth borrowing
### 1. Make video an inspectable build artifact
The final output is MP4, but the source remains HTML, CSS, assets, and animation configuration. When generation fails, you can locate the specific structure responsible instead of guessing from a prompt.
### 2. Use skills to define production workflows
`/hyperframes` handles routing. Specific tasks then enter workflows for product videos, PR videos, subtitles, or motion graphics. Every workflow reuses the same lint, preview, and render tools.
### 3. Connect design rules to the video project
The README provides `frame.md` to turn an existing design specification into rules video frames can use. The agent does not need to guess font, proportion, and composition constraints each time.

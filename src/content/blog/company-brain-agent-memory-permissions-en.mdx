## Evidence card
The official announcement confirms that Supermemory shut down the hosted Company Brain service on September 9, 2026 and refunded paying users. The official repository README says the discontinued product is now fully open source and runs in users' own Cloudflare accounts.
The permission documentation divides memory into three scopes. Information from public channels enters shared organization memory. Private-channel information enters only that channel's memory. DMs create personal memory. Queries in public channels can use only public memory. Queries in private channels can also read that channel's memory. DM queries can additionally read the asker's own personal memory and memory from private channels the asker has joined.
Tool permissions are also tied to user identity. Reads use a personal connection first, falling back to a shared organization connection only when none is available. Shared organization connections cannot write. Writes such as creating issues or commenting on PRs must use the asker's own personal connection. If only a colleague has connected a tool, Company Brain sends an approval card in Slack, and the authorization applies only to the current request.
## The 30-second version
Supermemory first shut down Company Brain's hosted product and has now open-sourced the complete codebase. It remains a team agent inside Slack, but its permission map is the part most worth examining. Public channels, private channels, and DMs do not share one large memory pool. Information is written to the narrowest room, and the readable scope expands at answer time according to permissions the asker already has. Tool writes also cannot use a shared organization account directly; they must go through personal connections. This gives a concrete implementation of team-agent permissions, beyond simply "adding memory."
## Why it is interesting
Most team-knowledge agent demos emphasize how much the agent remembers. Company Brain builds harder questions into the product's structure: which room produced a memory, who may read it, in which room it may be retrieved again, and who is allowed to change external systems on the team's behalf.
The product's status is another point of interest. Supermemory closed the hosted service on September 9, and the open-source repository now turns the original product into a self-hosted one. It is complete product code that real users used before commercial hosting ended, rather than a concept demo.

<td>Organization connections support shared reads, while writes must bind to personal connections.</td>

<td>Request one-time authorization when permission is missing</td>
<td>If only a colleague has a connection, send an approval card asking that person to explicitly allow the current request.</td>

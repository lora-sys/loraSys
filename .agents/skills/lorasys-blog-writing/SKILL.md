# loraSys 博客写作

统一事实表达、组件语义和阅读体验。不同文章保留自己的叙事与篇幅，不套固定段数，不要求每篇都有摘要卡、流程图或图表。

## 先读当前规则

以当前仓库根目录为工作目录。先读 `AGENTS.md` 与 `docs/mdx-content-contract.md`。涉及分类时读 `src/content.config.ts` 和 `src/data/writing-taxonomy.json`。涉及展示时读本 skill 的 [展示选择与示例](references/presentation.md)。

文字以 unslop 为主。每次写作读取 [文字规则](references/writing.md)，这是按维护者指定的 unslop 与内联规则整理的仓库版本。会话已有完整内联规则时直接采用，不必重复读取同样内容。环境中有 unslop skill 时也遵守它，冲突以维护者当前指令为准。用户要求查看原文时读其指定路径。不要把个人机器的绝对路径写进文章或模板。

组件与字段以当前源码为准。文档与源码有冲突时，检查 `scripts/validate-blog-mdx.mjs`、`src/pages/blog/[...id].astro` 和 `src/components/blog/mdx/`，记录冲突，不通过修改组件或校验器绕过内容限制。

## 写作流程

1. 确认任务是新稿、导入、同步、翻译还是已有文章维护。列出源材料、已有 slug、分类、媒体和需保留的展示。普通导入稿先进入 `content-drafts/review/`。只有已获授权的内容同步才按现有清单直接更新公开目录。
2. 先写读者需要知道的事实。开头说明对象、用途和本文要解决的问题。机制文章讲触发条件、参与者、过程和限制。实践文章区分计划、实际操作、结果与未验证项。指南写前置条件、步骤、预期结果和失败处理。阅读清单对每条写具体变化、适用范围和来源。不强制所有文章使用这些标题。
3. 核对事实。外部项目写清作者或组织与原始链接。区分来源报告、作者实测、推导、教学示例和个人判断。数字注明单位、时间、条件和来源。推导写出依据。没有证据就删除结论或写清待核实，不编造补齐。
4. 先用普通 Markdown 完成可读正文，再选择能减少读者理解负担的组件。正文必须独立说明关键结论，不让读者必须点标签或运行交互才能理解文章。
5. 做 unslop 改写。删除套话、夸饰、空泛比喻、无来源归因、抽象术语堆叠与重复结论。保留作者判断，但写清判断依据。一个概念用一个称呼，一句表达一个意思。不要为组件数量强凑三点。检查破折号、括号、装饰表情、过度加粗和标签式列表。代码、公式、URL、YAML 与组件语法保留必需符号，不用文字清理破坏语法。
6. 核对元数据、媒体和已有增强，再执行适用检查。最后报告修改文件、事实或附件缺口、实际完成的验证。未运行的检查不能写成通过。

## 元数据与维护

- `title` 最多 60 字符，直接说明主题。`description` 最多 160 字符，说明文章提供的具体信息，不重复标题或写宣传语。
- 必填 `publishDate`、`contentType` 和 1 至 5 个不重复的 `topics`。分类 ID 只取当前 taxonomy。来源分类缺失、未知或与已审核文章冲突的同步候选进入审核，不默认归为 technical。
- `series` 只用于已有、适用的系列。保留历史 `tags`。不通过改分类制造新的文章内容。
- 已有稿保留 slug、首次发布时间、来源身份和公开链接。事实更新才按实际更新填写 `updatedDate`，不凭空设置日期。
- 中英文版本遵守相同事实与展示规则。翻译用当前支持的 `language`，`translationOf` 指向原文 slug，不指向另一篇译文。没有翻译任务时不自行新增译文。
- 已有文章更新前与当前 main 比较。保留仍有效的 Callout、图表、流程、标签和其他阅读增强。删除或替换时说明具体失效原因。保留 `content-sync/blog-visuals.json` 中已审核封面映射，维护记录沿用现有清单。

## MDX 与媒体边界

文章是声明式内容。组件由路由注入，不在正文中写 import、export、JavaScript 表达式、脚本、样式、事件处理器或 client 指令。组件参数使用静态字符串。JSON、代码和花括号示例放进 fenced code。普通链接使用 Markdown 链接，不用尖括号自动链接。

枚举源材料中的图片、文件、视频、音频、embed 和交互 HTML。逐项记录原始附件、站点文件、替代品或缺口。缺字节的附件写 blocked；重建内容写 reconstruction 并标明它不是原附件。正文同步成功不能代表附件全部同步。

图片放到现有本地资产路径，写有意义的 alt。原创插画遵循 Lora Field Notes，优化为 WebP 后接入，注明示意属性。研究图表和实测截图保留来源与证据身份，不把插画当测量结果。生成原图与审查材料放仓库外。

视频与交互 HTML 使用现有专用组件和允许的本地路径。交互 HTML 保留可读文字或表格回退。不添加远程脚本、追踪、提交表单或密钥。不要为文章新增框架、依赖、CI 或部署策略。

## 验证与交付

只编辑 skill 或说明文档时，校验 skill frontmatter、引用路径、示例与当前 contract，不启动浏览器或开发服务器。

改文章时运行 `bun run content:validate`。公开内容交付前按 AGENTS.md 运行 `bun run check`，要求 0 errors 与 0 warnings，并完成生产构建。PowerShell 使用以下环境变量方式执行构建。

`content:validate` 只扫描 `src/content/blog/`，不会扫描审核候选。验证候选时在仓库外创建隔离副本，保留所需脚本、清单与已审核媒体，将候选复制到该副本的博客目录再运行现有校验。不要为了验证把候选放进真实工作区的公开目录。校验通过不改变候选的审核状态。该校验检查内容规则，不代替 MDX 编译或生产构建。

```powershell
$env:NODE_OPTIONS = '--max-old-space-size=3072'
bun run build
```

有交互或新增可视化时检查生产预览中的桌面、窄屏、键盘和减少动态模式。等待真实 DOM 状态。检查懒加载图片前滚到图片位置，再等待 complete 与 naturalWidth。截图放仓库外。首页或作品页受影响时才按仓库要求补 Lighthouse。

遇到现有失败先保留工作区修改并定位来源，报告与本次任务的关系。不要覆盖他人修改、重写已审核 SVG、改 CI 或宣称失败与本次任务无关而不给证据。内容编辑不自动授权提交、推送或发布。

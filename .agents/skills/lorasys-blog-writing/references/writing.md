# 文字规则

本规则按维护者指定的 unslop 和会话内联版本整理，供没有全局 unslop 的仓库 Agent 使用。它约束文章正文、标题、描述、图注和交互提示。代码、公式、链接与组件参数的必要语法不按散文标点处理。

## 改写方法

先找空话、重复、夸饰和无来源结论。改写时保留事实、原意和作者语气。最后再读一遍，删除换个项目仍能照搬的句子。

写清机制、操作、事实或数字。执行者已知时用主动语态。执行者未知或不重要时可以用被动语态。长句拆开，一句一个意思。写完整句子，不为简短省掉必要成分。

作者可以写自己的选择、经历与判断，但要给出具体依据。不为增加个人声音编造感受、经历或观点。复杂问题写出具体限制，不用含糊保留词掩盖缺证据。

## 删掉这些表达

- 删除客套、奉承、聊天机器人开场、无信息铺垫和泛化结尾。
- 删除宣传词、夸饰、抽象比喻、拟人化代码和刻意警句。用准确动词、机制或可验证数字替换无实质修饰。
- 不写 "不只是 X，更是 Y"。直接说明事实。不强凑三点，不用没有合理尺度的 "从 X 到 Y"。
- 不写 "专家认为"、"研究表明" 等无具体来源归因。有来源写明作者、文档或论文，并在相关事实旁放链接。没有来源就删除归因。
- 用 "是" 和 "有" 代替花式表达。用 "使用" 代替 "赋能"、"撬动"、"杠杆" 等抽象动词。
- 一个概念保持同一称呼，不为避免重复轮换近义词。术语首次出现时解释与本文有关的含义，不堆缩写。
- 减少副词和多重保留词。写实测变化与条件，不写 "显著提升" 来替代证据。

## 标点与排版

正文不用破折号、括号或替代性横线分隔句子。需要补充时另写一句。冒号只用于引出列表或例子，不连接两个句子。引号使用直引号。

少用加粗，不用重复正文的标签式列表。不加装饰表情。标题采用句首大写，保留专有名词的正确拼写。列表只用于步骤、真正并列的条目或便于对照的信息，不为了版式拆碎段落。

不要用箭头代替正文中的完整关系描述。流程图与代码可按其语法使用箭头。Markdown 表格分隔行、文件名、URL 和代码中的连字符保留。

## 最后自查

读者能否从每段得到具体事实、操作或判断依据。数字是否有单位和来源。作者观点是否与来源事实分开。有没有为了组件数量重复文字或凑结论。删掉空洞结尾后，文章是否已经说明结果与限制。
